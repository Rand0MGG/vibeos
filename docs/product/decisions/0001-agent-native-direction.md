# 决策 0001：采用 Agent-native 个人计算方向

状态：已接受
日期：2026-07-15

## 背景

早期 VibeOS 实现和文档主要围绕受限 capability executor、GNOME 桌面动作、
审批和 GoalLoop 展开。该架构建立了良好的安全、恢复和审计基础，但容易把
产品理解为“自然语言调用少量桌面能力”。

项目真实愿景更广：Agent 应能够像真实用户一样使用电脑，同时利用 API、
命令行和系统状态获得超越普通用户的理解与执行能力。

## 决策

### 1. 产品身份

VibeOS 定位为 Agent-native 个人计算运行时，而不是新的命令解析器或仅依赖
GUI 的 computer-use 工具。

### 2. 执行层级

Agent 同时拥有结构化和图形操作能力，默认优先顺序为：

```text
API
-> CLI 和系统工具
-> 系统服务
-> Accessibility
-> 结构化 UI
-> 鼠标、键盘和视觉
```

Shell 从长期禁止项改为一等受治理能力，但不得绕过权限、秘密、审计、验证
和回滚。

### 3. 自主性

目标明确后，Agent 自主处理技术步骤、错误、等待和策略切换。目标或现实
后果模糊时，Agent 必须先询问用户。

### 4. 用户批准边界

付款、外部通信、公开发布、私人数据外传、重要数据删除、账号和安全策略
修改、接受协议以及其他不可逆承诺必须由用户批准。

### 5. 提权

主 Agent 不持有永久 root 权限。它提交结构化请求，由确定性策略和独立
Reviewer Agent 审核，Privilege Broker 使用限时、限范围 Lease 执行。

Reviewer Agent 是 VibeOS 自动运行且与执行者隔离的审核角色。可回滚的 E2
提权默认不要求用户逐次批准；Reviewer 无法确认边界或动作属于 E3 时才交给
用户。执行主 Agent 不得成为自己的唯一授权者。

### 6. 回滚

系统级动作必须被标记为可回滚、可补偿或不可逆。可回滚特权动作在执行前
准备快照、备份或逆操作，执行后验证；失败时自动回滚并再次验证。

### 7. 秘密

Agent 和模型只持有 Secret Reference，不读取密码、Token、Cookie 或私钥
明文。Secret Broker 将秘密直接注入受信目标。

### 8. 模型

高质量推理主要使用 GPT、DeepSeek 等云端模型。本地确定性策略和本地模型
负责隐私硬边界、分类、裁剪、摘要和低成本任务。建立独立 Context and
Model Router。

### 9. 长期任务和主动行为

任务需要支持数小时运行、等待、暂停、重启恢复和用户接管。Agent 可以主
动发现并报告问题，但默认由用户决定是否创建解决任务。

### 10. 产品与平台

VibeOS 同时是设备所有者的本地个人 Agent 和可扩展能力平台。扩展必须服
从 Core 的权限、数据、任务和审计边界。

### 11. 发行版路线

近期先在现有 Linux 发行版上交付 Runtime。只有当事务、回滚、权限、秘密
和 Agent 生命周期受到现有系统实质限制时，才启动独立 VibeOS Linux。

## 后果

### 正面后果

- 产品目标从能力数量转向真实任务完成；
- API、CLI 和 UI 可以在一个任务中协作；
- Agent 可以比用户更深入地理解和管理设备；
- 长期任务、秘密、提权、回滚和模型隐私获得明确架构位置；
- 保留发展为 Agent-native Linux 的长期空间。

### 成本和风险

- 威胁模型显著扩大；
- Shell、root、云端模型和 UI 控制会形成复杂组合风险；
- Machine Model 可能造成新的隐私和数据保留问题；
- 回滚不能覆盖付款、通信和数据泄露等不可逆动作；
- 独立 Reviewer 仍可能判断错误，必须由硬策略和系统边界约束；
- 从当前 capability executor 演进需要分阶段垂直迁移、验证和删除旧路径。

## 实施约束

- 不得先开放无限 Shell/root，再补治理层；
- 不得让执行主 Agent 成为自己的唯一提权审批者；
- 不得把秘密交给模型后再依赖提示词要求它忘记；
- 不得把 UI 操作当成唯一或默认执行方式；
- 不得把 WSL、fake adapter 或 dry-run 当成真实 Linux 产品证据；
- 不得因为长期发行版愿景而延迟现有 Linux Runtime 的用户验证。

共同技术底座、Privilege Broker 的首选 Linux 机制和迁移原则已经在
[决策 0002](0002-implementation-foundation.md)中确定；以下具体参数仍由阶段
基准和真实 VM 决定：

- 最小 Machine Model 范围；
- 首批特权和可回滚动作；
- Privilege Broker 是否需要自有 Rust helper，还是可完全复用现有系统 D-Bus API；
- D2 私人内容的默认云端策略；
- 长期授权的粒度和默认期限；
- 发行版启动的量化门槛。
