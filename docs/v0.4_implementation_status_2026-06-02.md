# VibeOS v0.4 Implementation Status

Last updated: 2026-06-02

## Scope

This document records the implementation progress for `docs/v0.4_goal_for_codex.md`.

The goal document itself remains unchanged. This file is the maintenance record for the code that was actually added in the repository.

## Implemented In Code

### Domain, context, and verification architecture

- Added typed v0.4 models in `src/vibeos/domain_models.py`:
  - `ContextBudget`
  - `DomainPack`
  - `ObservationRequest`
  - `ResolvedContextPackage`
  - `ObservationReceipt`
  - `CapabilityExposure`
  - `DomainRoutingResult`
  - `VerifierResult`
  - `ScenarioFixture`
  - `RunTrace`
- Added plain-data registries in `src/vibeos/domain_registry.py`:
  - `DomainRegistry`
  - `ContextPackageRegistry`
  - browser/media route definitions
  - browser/media domain packs
  - bounded context package definitions
- Added router stage in `src/vibeos/domain_router.py`.
- Added bounded observation resolution in `src/vibeos/observation.py`.
- Added verifier registry and fake/local verifier harness in `src/vibeos/verifiers.py`.
- Added run-trace serializer in `src/vibeos/run_trace.py`.

### Planner narrowing

- Reworked `src/vibeos/planner.py` so browser/media requests now use a domain-scoped planning path:
  - `UtteranceAnalysis`
  - `DomainRoutingResult`
  - `ObservationRequest`
  - `ObservationReceipt`
  - `CapabilityExposure`
  - candidate plans from active domains only
  - structured trace payload
- Kept legacy v0.3 fallback behavior for non-domain requests and unsupported browser/media shapes.
- Added explicit media-to-browser fallback behavior rather than implicit omission.

### Browser vertical slice

- Added planner-visible semantic browser capabilities:
  - `browser.open_url`
  - `browser.search_web`
  - `browser.open_site_search`
- Added browser-domain routes:
  - `browser_open_url_route`
  - `browser_search_web_route`
  - `browser_site_search_route`
- Browser execution still reuses the lower-level `portal.open_uri` adapter, but the task plan and policy layers now expose browser-level semantics.

### Media partial vertical slice

- Added planner-visible media capabilities:
  - `media.search`
  - `media.play`
  - `media.pause`
- Added dedicated media route planning plus explicit browser fallback route selection.
- Local execution for dedicated media remains unavailable by design; fallback is now explicit in route selection and provenance.

### Policy and validation updates

- Extended `src/vibeos/capabilities.py` with browser/media semantic capabilities.
- Extended `src/vibeos/permissions.py` with browser/media target validation rules.
- Extended `src/vibeos/task_models.py` and `src/vibeos/task_validation.py` for v0.4 route metadata and schema handling.
- Adjusted deterministic route scoring in `src/vibeos/routes.py` so dedicated media routes win over fallback routes when the required capabilities are actually available.

### Broker, CLI, and offline acceptance

- Wired `src/vibeos/broker.py` to:
  - carry v0.4 planning payloads
  - keep structured trace data
  - execute browser semantic actions through the portal adapter
  - attach structured verifier outputs to plan execution results
- Added deterministic offline acceptance support in `src/vibeos/cli.py`:
  - `vibe plan ... --offline`
  - `vibe ask ... --offline`
- Offline mode forces `RuleIntentBroker` and does not depend on missing environment variables or remote broker failure.

### NLU updates

- Reworked `src/vibeos/nlu.py` to cleanly support:
  - English browser URL open requests
  - English browser search requests
  - Chinese browser/media acceptance examples from the v0.4 goal

### Test support

- Added `tests/conftest.py` so repo-root and `src/` imports are stable under pytest.
- Added `scripts/__init__.py` so `tests/test_vm_evidence.py` can import `scripts.collect_vm_evidence`.

## Ready For VM-Oriented Real Testing

The repository is now at the point where v0.4 code can be moved into a VM for real-session testing.

What is ready:

- domain-scoped planning path
- bounded context exposure
- semantic browser planning/execution path
- explicit media fallback path
- typed verifier infrastructure
- deterministic offline acceptance path
- full local test pass

What still requires real VM evidence:

- real browser launch and URL/search observation against a live Linux desktop session
- real desktop/session context producer behavior instead of the current local-safe unavailable/mockable defaults
- dedicated media execution adapters, if they are added later
- VM-side proof that browser semantic routes and verifier hooks behave correctly against real session state rather than only fake/local harness observations
